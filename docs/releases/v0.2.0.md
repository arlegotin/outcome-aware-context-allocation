# 0.2.0 — Evidence-first reader research

This release contains a positive reader endpoint and an inconclusive allocation
thesis. It preserves the original experiment and adds separately frozen
reader-recovery and evidence-first protocols. The evidence-first prompt remains
experimental; the unchanged reader is still the control.

## Measured reader result

All 128 assigned calls on 64 reserved validation questions completed before Gold
was opened. Two fresh scoring processes returned identical scores and closure.
Both conditions used the same 4B model, retrieval, ten natural paragraphs,
decoder and complete warm request boundary.

| Condition | Strict successes /64 | Answer matches /64 | Mean seconds/query |
| --- | ---: | ---: | ---: |
| Unchanged prompt | 6 | 33 | 2.5919 |
| Authored evidence-first prompt | 19 | 44 | 2.7200 |

The simultaneous strict-EM difference interval was **[+0.094, +36.991] percentage
points**. The answer-EM interval was **[−5.767, +36.862] percentage points**. The
strict endpoint improved, but the full frozen admission rule failed because
answer preservation was not established. Mean request time increased 4.94%.
Sparse successes make the prespecified efficiency interval unavailable. There
is no demonstrated efficiency, outcome-trained routing or operational win.

No new routing labels were acquired and no final allocation comparison was
launched. The final 128-question reservation remains untouched. No actual service
requirements were supplied, so operational success remains unassessed. Exact
benchmark citation agreement is not a human certificate of semantic support.

The [full report](../experiments/2026-10-15-evidence-first-validation.md) contains
the frozen gate, failures, accounting, latency, source identities, independent
aggregation and blind annotation-review limitations. The earlier
[32-question diagnosis](../experiments/2026-10-15-reader-recovery.md) is a distinct
160-call experiment, not additional validation observations.

## Software and evidence

- Recursive index-lineage validation binds parent manifests, vectors, completed
  attempts and ledger intervals, preserves failed costs and detects corruption,
  conflicting identities and cycles. Historical seals remain immutable.
- The new `python -m outcome_poc.reader_recovery --help` interface reuses existing
  lifecycle, parsing and scoring primitives with explicit continuous clocks,
  source/model/prompt bindings, closed assignments and private-data isolation.
- Reservation guards preserve exposed and unexecuted cohorts. Future preparation
  fails closed when required private reservation metadata is unavailable.
- Public [diagnosis evidence](../../experiments/reader-recovery-v1/evidence/evidence-manifest.json)
  and [validation evidence](../../experiments/reader-evidence-first-v1/evidence/evidence-manifest.json)
  contain aggregates and content identities. Benchmark text, Gold, predictions,
  private review packets, model files and raw archives remain local.

Native software verification targets Python 3.12/macOS ARM64 with the unchanged
hash lock. The delivered implementation passed 1,119 tests with no skips,
including seven parity cases against the authenticated official evaluator.
Without `HOTPOT_EVALUATOR_PATH`, those seven cases explicitly skip. A fresh clone
needs no benchmark or model assets for software tests. Native controlled suspend
and reboot validation were not performed. Passing tests does not establish
useful quality or allocation efficiency.

The separate [release verification receipt](../../artifacts/provenance/release-v0.2.0-checks.json)
records the tested clean-clone commit and source/test identities, native test-log
hash, official citation-schema validation, package hashes and public-file review.
Package builds reuse the pinned environment without dependency resolution.
GitHub's tagged source archive contains the reports and configurations; the wheel
and package source distribution contain the Python package and legal notices.
Scientific dependencies still require the platform lock and model/data assets
remain external.
