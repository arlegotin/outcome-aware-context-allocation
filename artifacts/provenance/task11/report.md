## Cache implementation and fallback

The installed `mlx-lm 0.32.0` path was inspected before implementation. It accepts cached state only with the uncached suffix. Its final prompt callback is already after generated-token lookahead, so that callback is never used for capture.

The adapter creates fresh per-layer KV state for the draft. At the first synchronized intermediate prompt callback covering the actual common-token prefix, it deep-copies the cache **before any draft continuation**, trims the independent snapshot to `min(common_prefix, draft_length-1, target_length-1)`, and checks every layer offset. This guarantees a nonempty suffix for recomputing logits even with identical prompts. The ordinary draft continues using its original state. The full call consumes the snapshot once and supplies only the uncached suffix. No generated draft token enters the target prompt or its active cache.

The handle binds query/job/attempt scope, exact source prompt hash, full target token sequence, installed template, model hash/revision, backend settings and all generation request settings other than the intentionally different prompt hash. Changed question/evidence/template/request/model and repeated use reject. A worker restart loses the handle and fails rather than silently generating a fresh replacement. The runtime builds/binds the full target before the draft; its document reads/rendering and clone work are included in serving time.

Synthetic regression tests exercise first divergence, `C=0/1`, 255/256/257 allocation boundaries, 511/512/513 prefill boundaries, identical prompts/one-token suffix, clone isolation after draft mutation, stale identity and source-event lineage. Existing EOS/cap/timeout/supervisor tests remain green. Real EOS behavior appears in the question cases; native synthetic boundary calls all reached their 16-token cap. A focused timeout fixture confirms the paid partial token payload survives, the captured clean handle is discarded and reuse cannot trigger another backend call. This is fixture evidence, not a forced native timeout run.

Nine synthetic boundary cases also had exact tokens and logprobs. `runner.optimistic_post_cost(events, reusable_prefill_seconds)` therefore remains required for comparisons. It removes at most the measured clean full-call chunk-prefill amount, retaining retrieval, entire paid draft, routing, prompt preparation, cloning/other work, full decoding, final prompt-token processing and sampling. The deliberately optimistic envelope removes even noncommon full-prompt chunks; it is **not** an exact common-prefix duration. Bounds reject negative/nonfinite or unmeasured/excessive subtraction. Backend `prompt_tps` includes callback/first sampling/lookahead overhead and is never substituted for reusable prefill. Candidate margins erased by this bound remain unresolved.
